# AGENT.md

Guidance for the coding agent in this repository. It contains only the persistent instructions needed for this project.

## What this is
This repository implements the backend service for collecting HTTP traffic generated by client agents and persisting it for security analysis.

The success criterion is a working backend that authenticates users and agents, accepts traffic logs securely, and stores them in MongoDB without leaking sensitive data.

Authenticate and bound uploads before durable raw receipt; validate, minimize and
protect their content in the parser before silver/Mongo log persistence. Never
log raw payloads or credentials.

## Optional agent skills

Skills are local coding-assistant tooling, not application dependencies; building,
running and testing the product does not require them. The only project skill is
**`auth0`** from [Auth0's official agent-skills repository](https://github.com/auth0/agent-skills).
It covers both FastAPI and Next.js through framework-specific references.

To restore it from the repository root, use Node.js 22.20+ and npm:

```bash
DO_NOT_TRACK=1 npx --yes skills add auth0/agent-skills --skill auth0 --agent github-copilot --yes
```

This installs the current upstream skill at `.agents/skills/auth0/SKILL.md` and
generates `skills-lock.json`. Both are intentionally ignored, as is the alternate
`skill-lock.json` filename; do not commit downloaded skills or their lock files.
No upstream skill version is pinned by this repository. See the
[Skills CLI reference](https://github.com/vercel-labs/skills/blob/main/docs/commands.md#skills-add)
for other agents or a global installation.

## Always keep in mind
- Secrets belong in git-ignored `.env` files or externally provisioned Kubernetes Secrets, never in source files or logs.
- Authentication and authorization are mandatory for every sensitive route.
- Data minimization matters: do not log raw secrets, tokens, or credentials.
- Keep the application Python-first and avoid introducing unrelated infrastructure complexity.

## Architecture in brief
- `app/main.py` creates the API app and registers all routes.
- `app/api/` exposes endpoints for auth and traffic ingestion.
- `app/services/` contains business logic for authorization, ingestion, and log handling.
- `app/db/` persists data to MongoDB.
- `app/core/` contains config, security helpers, and structured logging.
- `app/api/uploads.py` accepts durable raw uploads to GCS (local MinIO).
  Object-event Pub/Sub triggers `app.spool_worker parse`; protected normalized
  documents cross silver Pub/Sub to `app.spool_worker load` for rate-limited
  majority Mongo writes and raw cleanup. This is the sole ingestion pipeline.
  POST acknowledges raw receipt; content validation fails asynchronously.
  See the [ingestion design](docs/INGESTION.md) and runbook.
- `frontend/` is the JavaScript/JSX Next.js SSR management console with shadcn/ui.
  Read its README before changing it. API tokens stay server-side; no browser
  token endpoint or cross-owner bypass is permitted. Use `make frontend-test`,
  `make frontend-build`, and `make frontend-test-browser` for its validation.
- OpenBao Transit wraps EC keys stored as ciphertext in KV v2; only the KEK is
  non-exportable. Backend decryption uses EC keys cached in RAM, never plaintext
  key files or private EC Kubernetes Secrets. See `docs/ENCRYPTION.md`.

## Change these together
- API route and schema: if the request body changes, update both the HTTP contract and validation schema.
- Service logic and tests: every auth or ingestion rule must be covered by tests.
- Storage model and persistence code: schema changes must be reflected in MongoDB models and any consumer code.
- Implementation changes and visual documentation: update affected high-level,
  development and production architecture diagrams, operation sequence diagrams
  and their index in `docs/IMPLEMENTATION_STATUS.md`. Add sequences for new
  operations and keep links current. Preserve these visual views even when they
  overlap prose; do not remove them during documentation consolidation.

## Tests
- Unit tests cover validation, auth decisions, and service logic.
- Integration tests validate MongoDB-backed flows.
- `make test-stack` runs the HTTP-only two-device OAuth test in `integration_tests/`;
  it requires a running stack and two dedicated client credential pairs in the
  ignored `.env.stack-test`. See the runbook before running it against real services.
- Security tests ensure unauthorized access is rejected and sensitive data is not logged.
